A · What was run

Four hyperparameters were varied at once. Trying every combination would take 4 × 3 × 3 × 3 = 108 runs; we ran 36 — one third of them — picked so that the comparisons still come out fair.

What makes them fair is that every pair of settings occurs together the same number of times. Compare steps=3 against steps=7, for instance, and the two groups of 12 runs contain exactly the same mix of lookback windows, hop depths and prompts. Nothing else differs systematically between them, so a gap in AUC belongs to steps and nothing else — no statistical adjustment is needed, and none is used anywhere in this report. (Formally: a strength-2 orthogonal array, OA(36, 4¹3³, 2).)

This was checked twice — against the 36 config files before dispatch, and against the returned MLflow runs afterwards. Each lookback value appears in 9 runs; each steps, hop and prompt value in 12. All six factor pairs are complete, with no missing combination and each pair occurring 3 or 4 times depending on how many levels the two factors have.

C · Do path-chain features help?

No detectable effect. This is the sweep's central negative result.

path_mean_norm is the mean Euclidean length of each day's 384-dimension path vector, averaged over the run: 0 means the block is entirely zeros, ≈0.79 means most days carry real chain embeddings. It is preferred to nonzero_frac, which reads 1.0 as soon as a single day contributes, because embeddings are dense.

D · Differential analysis by factor

Runs vary far more than factors do. Across the 36 runs AUC has SD 0.065 around a grand mean of 0.617, and the furthest any factor level sits from that mean is 0.028 (hops = 4, at 0.589). So the strongest hyperparameter effect in the whole design, 0.028, is under half the size of the ordinary scatter between runs, 0.065. Residual variation dominates the design.

F · Caveats

  • No text + graph arm. build_day_feature_vector skips text entirely, so the evolved arm is 488 structural dimensions with no text while the baseline is mean-pooled article embeddings with no graph. The two are disjoint, so the sweep cannot say whether the graph adds to article text — only which of the two wins alone.
  • Short validation windows (~42 days) against 488 structural dimensions. AUC ranges 0.469–0.787 across configs differing only in lookback; the noise floor is high and the feature count exceeds the day count.
  • n = 9–12 per factor level. Adequate for large effects only; nothing here should be read as a precise effect size.
  • Stochastic evolution. Identical settings have produced path signal differing sixfold. Run-to-run variance may exceed factor effects.
  • The schema is advisory, not enforced. Every ontology inherits additional_node_types / additional_relationship_types / additional_patterns = true from create_base_ontology(), so the extractor may introduce types and patterns the schema never declares. Sweep graphs were ephemeral sidecars, so conformance was never measured on these runs.
  • Single ticker. All conclusions are TSLA-specific. MSFT is queued but unrun.

G · For discussion

  • Add a text + graph arm. Without it the sweep cannot answer whether the knowledge graph contributes anything beyond article text — which is the project's actual claim. This is a change to build_day_feature_vector, not to the design.
  • Should the schema be enforced? With additional_* left true, ontology evolution is a suggestion to the extractor rather than a constraint. Enforcing it would make evolution a real intervention — and would change what every result here means.
  • Step 1 is accepted unconditionally — _should_accept_step (orchestrator.py:657) returns True whenever best_auc is None, which it is until a step is accepted. Gating it against the text baseline is a one-line change and would make "evolution never degrades the baseline" true by construction rather than false by accident. Re-run the sweep under that gate?
  • Path features cost real compute and contribute nothing measurable here. Change the feature construction, the downstream task, or the claim?
  • Is next-day direction the right target? It is near a coin flip, and may lack the signal to separate KG variants at this sample size.
  • Steps = 7 is hard to justify on this evidence — acceptance collapses after step 1 and the AUC gain over steps = 3 is +0.016.
  • Run MSFT as-is for replication, or fix the feature arm first?
